Generic review (`code-review`, medium) raised six findings, all fixed:

- The score shift took the lowest level the response reported, so a
  dropped zero-probability bottom level read every score one level low. It
  now anchors on the entry echoing the lowest label sent (`leave-it`), and
  otherwise uses the guide's numbering from 0.
- `probabilities` was parsed strictly, so an unexpected shape there would
  fail the run's triage. It is now read as raw JSON and can never fail an
  answer.
- With no `probabilities`, the numbering from 0 is now the documented
  contract rather than a silent default.
- A question answered more than once is an error, so a refusal can never
  hide behind an earlier answer under the same name.
- `wrong_type` and the unknown-kind check are shared in `provider/mod.rs`
  as `wrong_type` and `offered_kind`, used by both providers.
- Two doc comments no longer use semicolons.

Also found during QA: the refusal arm of `Answer::type_name` was
unreachable. A refusal is now caught before deserializing, and `Answer`
has no refusal variant.
