Reviewed T5: the release workflow, the demo, and the docs.

Decided with the user and written into the spec: `action.yml`'s default version is set in the release pull request beside `Cargo.toml`, and `the_action_installs_this_release_by_default` fails when the two differ. The release workflow moves `v1` itself.

Found along the way:

- With `uses: ./` the Action's scripts sit in the checkout the base-commit run replaces, so the demo would have had bash read `score.sh` while git rewrote or deleted it. The install step copies the scripts whole before any checkout, and `own-checkout` runs the Action inside a repository whose base commit lacks them.
- The demo set `CARGO_TARGET_DIR` from the runner context at job level, which GitHub rejects: the workflow never ran, reported as a failed push with no jobs. The seed step exports it.
- Five checks in the scenario jobs began with `! grep`, which bash's errexit skips, so they could not fail: the triage, args, update and empty-marker jobs were weaker than they read. They exit explicitly, and the Action scripts job runs actionlint over the three workflows, which catches both kinds of mistake.

Fixed in T5:

- `v1` moved on any matching tag, so `v2.0.0` or a prerelease would have moved it. It moves for 0.x and 1.x releases without a suffix, after a smoke job runs the Action with the just-published default on Linux, macOS and Windows, the one place the default version can be downloaded. The release trigger takes version tags only, so `v1` never starts a release.
- `llvm-tools` is added in the working directory, for a crate with its own toolchain file.
- The demo writes its config beside the shop, keeps its seeded triage cache out of every cache, and runs only on changes to the shop or its own workflow.
- The version test reads only under `inputs:`.
- The comment step uses `actions/github-script@v8` and the new workflows `actions/checkout@v6`, off the deprecated Node 20.

Left as is: the scenario jobs still use the v4 artifact actions, as `ci.yml` does, so a repository-wide upgrade is its own change. `@v1` exists from the 0.8.0 release on, so the README's snippet resolves once that release is tagged.
